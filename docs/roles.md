# 👥 역할 분담

> 2~4인 기준. 3인 이하면 역할을 겸임.

| 역할 | 담당 | 주요 책임 | 주 작업 폴더 |
|------|------|-----------|--------------|
| PM / 발표 | | 범위 관리, 시간 체크, 발표 자료·스크립트, 데모 시나리오 | `docs/` |
| Backend | | API 설계, LLM 연동, 모델 서빙 | `backend/` |
| ML / AI | | 데이터 수집·전처리, 모델 학습·평가, 프롬프트 설계 | `ml/`, `notebooks/`, `data/` |
| Frontend / Demo | | 데모 화면, UX, 시연 안정성 | `frontend/` |

## 겸임 예시
- **2인**: (PM+Frontend) / (Backend+ML)
- **3인**: PM+Frontend / Backend / ML

## 🔗 각자 개발 → 통합 규칙
1. **API 계약 먼저**: 위 표(경로, 요청/응답 JSON)를 확정하기 전에는 코드 작성 금지
2. **계약대로 가짜 응답부터**: 백엔드는 엔드포인트를 더미 값으로 먼저 열어두고, 프론트는 그걸로 화면 개발
   - LLM은 `MOCK_LLM=1`로 키 없이 개발
3. **담당 폴더만 수정**: 다른 사람 폴더 수정이 필요하면 담당자에게 요청
4. **계약 변경 시 즉시 공유**: 표를 먼저 고치고 PR에 명시
5. **통합 시점을 정해두기**: 예) 개발 시작 3시간 후 1차 통합, 이후 3~4시간마다
   - 통합은 `main` 최신 상태에서 백엔드 + 선택한 프론트를 함께 띄워 end-to-end 확인
6. **시연 환경은 1대**: 실제 API 키(`MOCK_LLM=0`)는 시연 노트북에만

## 소통 규칙
- 매 2~3시간마다 5분 스탠드업 (한 일 / 할 일 / 막힌 것)
- 30분 이상 막히면 바로 공유
- 기능 단위로 작게 PR → 빠르게 머지
